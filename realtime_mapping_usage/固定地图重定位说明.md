# 固定地图重定位测试

在 Ubuntu-22.04 中运行：

```bash
bash /mnt/d/未来机器人/realtime_mapping_usage/start_fixed_map_relocalization.sh
```

仅检查软件和地图，不启动雷达：

```bash
bash /mnt/d/未来机器人/realtime_mapping_usage/start_fixed_map_relocalization.sh --check
```

默认读取 `reconstruction_20261017_113920/raytrace/global_map.pc2.lcm`；雷达 IP 为 192.168.1.3，主机 IP 为 192.168.1.111。可用 `DIMOS_PREMAP`、`DIMOS_FASTLIO_LIDAR_IP`、`DIMOS_FASTLIO_HOST_IP` 覆盖。

该脚本复用 FAST-LIO2、RayTracingVoxelMap、LocalMapRelocalization 和网页 Rerun。原地图文件只读，关闭新的全局地图发布；FAST-LIO2 内部里程计地图和光追临时局部观测仍会更新，为匹配提供输入。当前阶段没有规划器、CAN 或底盘速度控制。

## 实验步骤

1. 关闭其他占用雷达的采集/建图程序，包括 Livox Viewer；车放到旧地图起点附近并保持静止。
2. 启动脚本，静止约 10 秒供 FAST-LIO2 初始化。全局特征匹配耗时取决于机器和观测质量，没有固定成功时限。
   如果启动时出现 `Apply these changes now?`，库正在等待确认配置本机 LCM 多播路由和接收缓存；输入 `y` 回车。出现 sudo 密码提示时，在原终端输入 Ubuntu 密码，输入过程不显示字符。在这项配置完成、Rerun 服务开始监听之前，网页会显示连接被拒绝。
3. 浏览器打开：
   `http://localhost:9878/?url=rerun%2Bhttp%3A%2F%2F127.0.0.1%3A9877%2Fproxy`
4. 关注 `world/local_map`（本次局部观测）、`world/loaded_map`（保存的地图，成功匹配后出现）、`world/tf`（含 mid360_link 雷达坐标轴）。开启 TF 坐标轴以正确展示不同坐标系间的变换。
5. 日志中 `align: fitness=... rmse=...` 是候选匹配质量；出现 `relocalize lidar: TF ...` 与 `placed, no further attempts` 表示通过当前算法阈值。仍需目视核对至少两个独立结构，如墙角和门框，排除相似走廊误定位。
6. 对齐后手动缓慢移动几米并转弯，观察墙面是否持续重合。当前只做一次全局匹配，之后依赖 FAST-LIO2 跟踪，不能据此认定长期定位无漂移。
7. Ctrl+C 结束。重新启动，在不同位置/朝向分别试验，记录成功与失败情况。

`No transform found` 在启动初期偶发可能来自 TF 尚未到达；持续出现则需要检查时间戳和 TF。`below fitness_threshold` 表示拒绝匹配，不应通过随意降低阈值强行接受。网页打不开或日志出现 ERROR 时保留完整错误信息。

当前可视化的位置是雷达位置。加入车辆安装外参、统一规划坐标系、校准静态通行地图后，才能进入 A→B 路径显示阶段。实车自动执行还需要独立验证 TRACER 控制接口。

## 2026-10-17 首次实机错位排查

首次实机匹配在约 5507 个局部点时以 fitness=0.624 接受了错误的朝向，之后因为只定位一次而锁定。只读捕获当前 43896 点局部观测后，当前变换的水平旋转约 -79.63°，重现了用户报告的接近 90° 错位。

对同一份完整局部快照进行了 4 个随机种子的离线匹配，4 次均得到相同候选：fitness=0.84129，水平旋转约 1.77°，平移约 [-0.157, 1.908, 0.017] 米。俯视切片显示它比原变换明显更吻合。它仍然是算法候选，不是带真值验证的定位结果；该变换仅属于当前会话，不能硬编码给重启后的里程计。

启动参数现改为：至少 30000 个局部点、fitness 阈值 0.8、RANSAC 候选 3 次取优、匹配间隔 3 秒。这是依据本次数据设置的排查参数，仍需重启后的实机验证。已有进程不会自动读取脚本变更，需要在原终端 Ctrl+C 后重新启动。原地图未修改。

诊断文件位于 `localization_diagnosis/`：`snapshot.json`、`candidates.json`、`current_overlay.png`、`best_overlay.png`。图中灰色为旧地图，红色为实时局部观测；图使用相同水平高度切片。
