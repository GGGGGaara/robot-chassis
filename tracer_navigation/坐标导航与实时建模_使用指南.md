# 坐标导航与实时建模（2026-10-23）

## 已完成的功能与当前边界

本版本支持以**每次发起任务时的底盘中心**为原点，输入前进／左移的目标偏移，生成并执行 Nav2 路线；导航时继续运行 `ku/dimos-main` 内的 FAST-LIO2 和光追三维建模。实时点云进入避障链，最新三维模型自动保存为 LCM 与 PLY。

导航使用已经保存的参考地图定位，三维重建模型另存。目标必须位于参考地图中已知、可通行的区域；本版本不进行未知区域自主探索，也不把新三维模型自动替换为导航底图。原图坐标因此能保持稳定。刚启动或重定位未成功时，不能执行目标导航。

设备断开期间已完成离线测试；实车坐标精度、避障效果、CAN 稳定性仍需重新验证。最高线速度 0.10 m/s、角速度 0.15 rad/s、规划路线总长上限 15 m，停车保护半径 0.70 m（从底盘中心量起），车高 1.20 m。安装参数仍是现场估计值，实车验收当前无效。

## 1. 先正确理解距离

现在会同时显示：

- `Straight A-B`：当前底盘中心至 B 的直线距离。
- `planned route including detours`：规划路线总长，包括绕障和转弯。
- 中止后的 `wheel-estimated travel` / `LIO travel`：任务实际走过距离的估计。
- `straight distance still to B`：距目标剩余的直线距离。任务中止不表示到达。

已查到历史记录 `results/mission_1792501806.json`：规划 3.489 m，轮速积分约 1.106 m，雷达里程计约 1.131 m，然后以 `latched_command_timeout` 中止。这符合“显示约 3 m、车只走约 1 m”的一种情况。轮速与雷达估计相近，不能据此把地图缩小到 1/3。

页面原先用雷达位置作为 A，而实车导航用底盘中心。本版已按安装外参统一到中心；该偏移约 0.4 m。距离审计也确认栅格原始分辨率与生成地图一致，约 0.08 m/格；安装矩阵是刚体变换，没有三倍缩放。但设备断开时无法确认现场实际比例，首次连接后需完成下面的尺量核验。

## 2. 连接设备与启动顺序

不要同时运行两套雷达／FAST-LIO2 进程。保留各终端，结束实验时先取消导航、确认停稳，再退出建模。

管理员 PowerShell 连接 USB-CAN：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\未来机器人\tracer_navigation\prepare_windows.ps1" -Connect
```

Ubuntu 终端 A 准备网络与 CAN：

```bash
bash /mnt/d/未来机器人/tracer_navigation/prepare_wsl.sh
```

这一步是只读反馈检查，不代表运动验收通过。底盘电源开，遥控器有电，SWA 上方、SWB 最上方、摇杆回中，物理急停可用。

终端 A 启动**重定位＋实时三维建模＋模型保存**：

```bash
bash /mnt/d/未来机器人/tracer_navigation/start_mapping_session.sh
```

查看器：

```text
http://localhost:9878/?url=rerun%2Bhttp%3A%2F%2F127.0.0.1%3A9877%2Fproxy
```

查看 `loaded_map`、`local_map`、`global_map`，确认墙角、门框多处位置和方向重合。必要时在遥控模式下低速补采，停稳后恢复 SWB 最上方。`global_map` 是本次会话逐步建立的模型；导航启动后还会显示 `live_scan`。模型含地面和环境，不将旧参考地图中的临时物体当作新观测。

终端 B 启动导航预览：

```bash
bash /mnt/d/未来机器人/tracer_navigation/start_navigation.sh
```

终端 C 检查：

```bash
bash /mnt/d/未来机器人/tracer_navigation/navctl.sh status
```

定位、感知有效，7 个节点 `active`；预览模式 `dry-run`、`armed: false`。此时底盘没有运动输出。

## 3. 距离核验（首次重新接线后做）

先在地面量取约 1 米的直线，使用同一个车身基准标记量起终点。导航保持未解锁。本工具只订阅定位和状态，**不会驱动车辆**：

```bash
bash /mnt/d/未来机器人/tracer_navigation/distance_audit.sh --record-seconds 30 --measured-m 1
```

看到 `START` 后，用遥控器沿量好的线低速走完并停稳，在 30 秒采样结束前保持静止。人工移动时 SWB 中间，结束后恢复最上方。采样中不要切换地图、重启定位或转弯；不要把 1 米远的目标和走过的曲线路程混为一谈。

报告 `results/measured_distance_*.json` 给出 `lio_to_measured_ratio`。例如约 1.0 表示两者一致；约 3.0 表示真实距离与里程计仍有明显差异，需排查雷达原始距离、安装／时间同步和定位跳变。工具不会自动缩放地图。`physical_scale_verified` 需要误差不超过 10%、轨迹接近直线；它是一次现场核验记录，不是正式标定证书。

只检查已有文件、不连接设备可运行：

```bash
bash /mnt/d/未来机器人/tracer_navigation/distance_audit.sh
```

## 4. 完成新版实车验收

在导航预览保持运行的情况下，终端 C：

```bash
bash /mnt/d/未来机器人/tracer_navigation/check_connection_zero.sh
```

要求完整 30 秒 `passed: true`、`ready_false: 0`、`all_motion_frames_zero: true`。旧版曾出现轮速／系统反馈超时，此问题未被证明修复；若仍失败，停止后续运动步骤，保留 `zero_driver_check.json` 和日志。不要调大 watchdog 来让检查通过。

现场清空车身、行驶与转向范围、留好线缆、手持急停后，依次进行：


## 5. 输入坐标进行导航

### 推荐的终端入口

两个位置参数依次是**前进米数、左移米数**。正 X 沿任务发起时的车头，正 Y 在车身左侧。左移表示目标的位置，差速底盘会转向行驶，不会横向平移。

只规划“前进 1 m、左移 0 m”，不解锁：

```bash
bash /mnt/d/未来机器人/tracer_navigation/navigate_relative.sh 1 0
```

只规划“前进 1.5 m、左移 0.5 m”：

```bash
bash /mnt/d/未来机器人/tracer_navigation/navigate_relative.sh 1.5 0.5
```

负左移为右侧目标。负前进是车后方的目标，导航仍禁止倒车，会尝试转向后行驶；转动空间不够时拒绝规划或停车。

现场已就绪、尺量和实车验收通过后执行：

```bash
bash /mnt/d/未来机器人/tracer_navigation/navigate_relative.sh 1 0 --execute
```

这条命令重新读取当时的底盘中心和车头方向，先规划并保存固定目标，再倒计时 20 秒，检查后执行一次。目标不会随车一起移动。倒计时中车身移动超过 0.15 m 或转动超过 5°时拒绝执行；重新输入命令才能生成新目标。两次运行同样的相对坐标，分别从各自运行时的位置开始计算。

绕障后的**路线总长**也必须不超过 15 m。默认任务最长 180 秒；较长路线可显式使用 `--timeout-s 300`，总上限 600 秒。首次实车验证先用 0.5–1 m 的空旷目标，不直接走满 15 m。

如果已有绝对地图坐标，也可只规划：

```bash
bash /mnt/d/未来机器人/tracer_navigation/mission.sh --xy 2.0 3.0
```

### 页面坐标预览（可选）

另开终端：

```bash
bash /mnt/d/未来机器人/realtime_mapping_usage/start_fixed_map_path_preview.sh
```

打开 `http://localhost:9880/`，输入前进、左移米数，点击“预览坐标目标”。页面显示底盘中心、1 m 比例尺、直线距离与绕障路线长度。页面只预览并保存 B 点，不直接使能实车。

如要执行页面选定的固定 B 点，沿用：

```bash
bash /mnt/d/未来机器人/tracer_navigation/mission_delayed.sh --execute
```

这与相对入口不同：它使用页面已保存的地图 B 点，不能在运行时自动平移目标。不要混用两套目标。页面失败的选点会使旧 B 点失效，离线演示手选 A 的目标不能用于实车任务。

## 6. 模型文件在哪里、内容是什么

本次运行自动创建：

```text
D:\未来机器人\tracer_navigation\model_sessions\日期_时间_随机编号\
  robot.yaml                  当次安装／底盘配置
  session.json                会话状态与起止时间
  latest.json                 最近一次完整快照的索引、帧和单位
  model_时间戳\
    global_map.pc2.lcm        DimOS 本次全局点云原始消息，odom 坐标
    model_map.ply             变换到原参考地图 map 坐标，单位米
    metadata.json             odom_T_map、时间、点数及原始消息 SHA256
```

大约每 10 秒保存一次有效模型，只保留本次运行最近两个完整快照；Ctrl+C 尽可能保存最后收到的模型。注册变换和全局点云必须新鲜，未重定位时不会产生地图坐标的模型文件。PLY 可在 CloudCompare／MeshLab 等点云工具中打开。它是三维点云模型，尚不是封闭三角网格或 CAD 模型。

快照目录写完后才更新 `latest.json`。检查该索引，而不是读取带 `.tmp` 后缀的未完成目录。参考地图 `reconstruction_20261017_113920` 不会被覆盖。

## 7. 故障处理与结束实验

| 输出／现象 | 下一步 |
|---|---|
| `Planner did not succeed` | 检查目标是否在已知可通行区、起点是否紧贴障碍、路线是否连通；不要反复解锁 |
| `latched_command_timeout` | 任务已中止；查看同一时段 controller/planner 日志。它不等于已经到达 |
| `wheel_feedback_timeout` / `system_state_timeout` | 底盘通信不稳定；停止运动验收，保留报告 |
| `mount_not_accepted` / 软件指纹变化 | 完成零速及前进／左转复验，按真实结果重新验收 |
| `Vehicle moved after relative target was frozen` | 倒计时后起点变化，重新输入相对任务 |
| 未建图区域或障碍占据起点 | 拒绝自动行驶；先调整现场与重新建图／定位，不能靠扩大 15 m 上限解决 |
| 没有 `latest.json` | 尚无有效的全局点云＋重定位变换，检查 A 终端和 `global_map` |

出现异常先用物理急停。软件辅助停止：

```bash
bash /mnt/d/未来机器人/tracer_navigation/stop.sh
```

确认实车停稳后，退出实车服务 B，再退出建模 A。断开设备前保留 `results`、`model_sessions` 和相应 ROS 日志。

## 8. 离线证据和实现文件

- `results/coordinate_mapping_20261023/`：单位／模型测试、Nav2 坐标入口测试、启动检查等证据。
- `results/distance_audit_20261023.json`：地图分辨率、变换及历史路线／实际行程审计。
- `closed_loop_relative_report.json`：真实 Nav2＋理想运动模型下的相对目标闭环，含遇障停车和恢复。这不是实车到达证明。
- `coordinate_geometry.py`：坐标转换、距离与行程计算。
- `coordinate_task.py`、`navigate_relative.sh`：输入、固定目标、倒计时及执行入口。
- `mission.py`：重新规划、验收、健康监控、到达／中止和停车确认。
- `mapping_session.py`、`model_recorder.py`：建模进程生命周期和原子快照导出。
- `realtime_mapping_usage/start_fixed_map_relocalization.sh --mapping`：调用 ku 原有 FAST-LIO2／光追建模并输出全局模型。
- `fixed_map_path_preview.py/html`：底盘中心预览、坐标输入、直线与路线距离显示。

本次改动未修改 ku 原有传感器驱动或建模算法，没有降低反馈 watchdog 或碰撞保护条件。
